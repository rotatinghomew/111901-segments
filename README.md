# 健身参与人群分群与社区随访名额分配

本项目围绕社区全民健身公共服务的本地分析资料。数据均为合成记录，文件字段与时间口径按各自数据文件表示。项目目录包含业务资料、分析软件包和基础数据检查。

## 环境与运行

需要 Python 3.11 或更新版本，无第三方运行依赖。进入项目目录后运行：

```bash
python -m unittest discover -s tests -v
```

检查合成资料与全部业务规则（30 个用例）。分析包位于 `src/segments`，可从 Python 导入；命令行入口：

```bash
PYTHONPATH=src python -m segments.run --data data --run-id run-0001 --out report.json
```

输入资料位于 `data/`，CSV 使用 UTF-8 编码和首行字段名，策略资料采用 JSON。

## 数据约定

所有居民、机构、地点与活动均为虚构标识，时间以数据字段的本地日期表示。空字段表示该资料没有登记值，不应据此推断业务事实；具体数据口径以相应字段和 JSON 政策文件为准。资料用于离线分析，不含外部服务或凭据。

## 分析流程与设计纪律

分析按固定顺序组织，每一步都可单独导入、单独测试：

| 模块 | 职责 | 关键纪律 |
| --- | --- | --- |
| `dataio` | CSV/JSON 加载与结构校验 | 空字段保留为 `None`；事件引用未知居民标识直接报错，不静默并入 |
| `identity` | 居民标识校对与家庭多档案关系 | 关系只有 pending/confirmed/withdrawn 三态；未确认或已撤回时不合并家庭证据、不共享联系授权，禁止自动拼约 |
| `features` | 机会可及性与参与行为特征（12 列，列序固定） | 闭馆与满员是供给侧事实，不作为失去兴趣的证据；可选记录缺失只打标不编造；每个特征带证据计数 |
| `clustering` | 无先验阈值的层次凝聚聚类 | 簇数由轮廓系数在数据上选择；输出每簇的判别方向（机会/间隔/偏好/趋势）；证据不足、小簇回落为 `unclassified`，不发稳定标签 |
| `stability` | 未来周与留出站点稳定性、跨期比较 | 站点供给收缩不能把整站切到负面人群；口径版本不一致或簇匹配质量低于 0.6 时**终止**跨期比较 |
| `allocation` | 有限随访名额分配 | 联系授权、技能适配、常跑范围、名额与承诺期限共同约束；欠覆盖片区按 `reserved_share` 保底，缺口显式报告"缺什么"；已接受服务锁定不改约；同一对象单轮不重复打扰 |
| `review` | 周会复盘 | 区分运营动作、重新参与与多站点机会变化；回访后的出席只报告时间先后，明确禁止归因给分群模型 |

### 四类可解释行为组

- `sustained_participation`（持续参与）：出席率显著高于总体，无需主动外呼；
- `opportunity_limited`（机会受限）：闭馆/满员暴露或取消率突出，对应供给侧支持（恢复课程、跨站替代名额），停课不是流失证据；
- `short_break`（短期中断）：失约、出席间隔拉长或近期走弱，对应低频关怀回访确认原因；
- `unclassified`（证据不足）：零事件、无机会记录、小簇或身份待确认，先补证据不贴稳定标签。

### 跨期比较的两种变化

新的分群运行（run）带口径版本号。`compare_runs` 在版本一致且簇匹配可靠时才输出居民级行为变化；版本不一致属于**分群口径切换**，匹配不可靠时直接终止比较并给出原因，运营不会把口径切换误读为居民行为变化。
